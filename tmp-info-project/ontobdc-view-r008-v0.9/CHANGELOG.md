# Changelog

- Fixed WorkStream/Gantt folder resolution accepting any folder with a `datapackage.json` instead of descending to the dataset required by the current Page. This caused successful folder permission to be followed by the misleading “selected folder doesn't contain a project” label. Transient errors now restore the connected label, and WorkStream refresh feedback preserves its SVG icon.

- Standardized the WorkStream iconography: the header refresh action now uses the shared icon-button treatment, and resource trees use theme-aware SVG file/folder marks instead of platform-dependent emoji glyphs.

- InfoBIM branding now falls back to the assets shipped in the installed `infobim` package whenever an InfoBIM project marker exists but project-local branding files do not. The generated Surface embeds the SVG markup and therefore remains fully local/offline.

## Unreleased

### Added

- `submitGlobalEvent(event)` is a direct, awaitable call into the Python listener. The Page hands over the event it just wrote to its data source and the promise resolves with `{eventId, sequence, status}` from the listener itself — only once the event is stored under the dataset's `.__ontobdc__/event/` *and* its JSON-LD is in the Surface journal with a sequence assigned. There is no queue, no receipt and no polling, so there is no window in which the Page believes the Surface knows and it does not. Anything short of a completed run throws, carrying the statechart state it stopped in.
- `ontobdc_view.component.adapter.global_event_listener` ships that listener into Pyodide: the real modules at their real import paths — the journal writer, the statechart states, the listener — so the code running in the browser is the code the test suite exercises, found under the same names. It can be shipped because each imports only the standard library, and packaging refuses a module that reaches for anything else rather than discovering it as a blank page in a browser.
- The container is mounted for Python on demand. A Page connected through SheetJS never mounted it, and the listener cannot write into a filesystem Python cannot see; the writes are synced back before the call resolves.

- `global_event_replay.js`, the Global Event replay runtime. A Surface's `#ontobdc-surface-jsonld` block is a build-time snapshot; everything that happened to the underlying data since it was generated is persisted after it as an append-only journal of Global Events. This module reads both, applies the journal to the snapshot in sequence order and writes the materialized graph back into that same block — once. Tiles keep reading `#ontobdc-surface-jsonld` exactly as they always did and simply find the current state there. It is emitted before the component modules, so the whole replay finishes before `customElements.define` upgrades any Tile: a Tile's `connectedCallback` never sees the pre-replay snapshot and nothing has to be re-rendered afterwards. It must be embedded inline like every other component script — a `src=` module is fetched, and on `file://` that fetch is cross-origin from an opaque origin and Chromium blocks it outright.
- The reducer implements `set`, `unset`, `add` and `remove`, all idempotent. `set` preserves an existing value's `@language`/`@type` unless the event replaces them, so an edit coming from a spreadsheet column (which carries no language tag) does not silently change the triple. Events below `data-snapshot-through` are skipped, a repeated `eventId` is applied once, an event naming an entity this Surface does not carry is reported without stopping the ones after it, and an event declaring an operation its type does not carry is refused rather than obeyed.
- `ontobdc_view.global_event_replay_source()`, plus `global_event_iris()` and `global_event_operations()`. Which occurrences the runtime accepts, and which graph operation each one carries, are read from BrasidataCenter's `presentation_event.ttl` at generation time (`view:GlobalEvent` and `view:appliesOperation`) — so declaring an event in the ontology is what makes it replayable, and the JavaScript holds no vocabulary of its own. An operation named in the graph that the reducer cannot apply fails the build instead of shipping.
- The runtime exposes `window.OntoBDCGlobalEventRuntime` (`snapshotThrough`, `replayedEventIds`, `lastSequence`, `errors`) for diagnosis and announces `GlobalEventsReplayed` once as an ordinary Component Event. The ontology gives that occurrence no `view:promotesTo`, so replaying persisted history never re-enters the promotion chain as if the user had just acted.
- Restoring a Surface from the back-forward cache now forces a real reload. The BFCache does not re-parse the document, so a journal appended while the user was away is simply not present and the page shows pre-edit values with no sign of being stale.

### Changed

- Saving a WorkStream field no longer asks for a full Surface regeneration. It used to write the regeneration request on every saved cell, so one edited value rebuilt the whole Surface. The field change is now persisted as a Global Event the Surface replays over its snapshot; the regeneration request stays exactly as it was, reserved for structural change, where a single overwritable file is the right shape because only the latest request matters.
- `saveWorkStreamField` emits `EntityPropertySet` after the workbook write completes, through one producer shared by both write paths (SheetJS and Pyodide+openpyxl). The predicate is resolved as an IRI — the container's own ICDD/facade linkset first, then the canonical `WORKBOOK_COLUMN_TO_PROPERTY` convention this Page already uses to read live values back into the graph. A column with neither mapping declines to emit rather than putting a column label where a predicate belongs, which is what the journal writer rejects anyway. A value that did not actually change emits nothing. The entity is the WorkStream's `@id`; its workbook `GlobalId` travels as provenance.
- The event type IRI is substituted into the generated script at build time from `view:appliesOperation "set"`, so the ontology is what says which Global Event carries a property assignment. A script left with an unresolved build placeholder fails generation.

### Removed

- The Surface no longer reads the WorkStream workbook. `onto-workstream-tile.js` installed a `refreshFromWorkbook()` on the Surface that recovered the `FileSystemDirectoryHandle` the WorkStream Page had stored in IndexedDB, loaded SheetJS, walked the container for the dataset folder, parsed the worksheet and patched the Surface JSON-LD — on every `PageLoaded` and every BFCache restore. It could not work on `file://`, which is the mode this Surface exists for: IndexedDB is partitioned by origin and `file://` documents get opaque origins, so the Page and the Surface routinely looked at different databases. The handle was absent, the code returned `0` without saying anything, and the visible result was a Surface that kept showing the value the user had just changed. A data change now travels as a persisted Global Event applied by the replay runtime before the Tile is even upgraded, so the Tile needs no refresh path at all.


### Changed

- The presentation event system no longer has a second, JavaScript-resident semantics. Promotion from Component Event to Shared Event is decided exclusively by a Python Listener running in Pyodide against `view:promotesTo` in Brasidata/brasidatacenter's `ontology/tool/ontobdc/abox/presentation_events.ttl`; the browser code has integration responsibility only. `onto-presentation-surface` lost `PRESENTATION_GLOBAL_EVENT_TYPES` — the hardcoded array of DOM event types it treated as semantically global wherever in the tree they came from — and with it the assumption that the Surface can discover a promotion by watching DOM traffic. Its bar (`part="event-bar system-log"`) is now written only by `announcePromotion()`, called once per Shared Event the Listener returned, so it shows promotions rather than every occurrence; the layout-mechanics notifications (`surface-tile-pinned` and friends) still dispatch as the element's imperative API but no longer appear on it. The Surface announces `SurfaceLoaded` after its first layout.
- Every Tile now announces what happened to it locally as a Component Event (`ontobdc:component-event`, bubbling and composed, carrying the semantic name in `detail.event`) and never decides whether that matters to anyone else: `TileOpened`/`TileClosed` (`onto-file-viewer-tile`, the four per-file preview Tiles, `onto-file-size-tile`), `TileExpanded`/`TileCollapsed` (`onto-workstream-tile`), `TileFullSized`/`TileRestored` (every Tile with a fullscreen control), `EntitySelected`/`EntityPageOpenRequested` (`onto-file-tree-tile`, `onto-photo-tile`) and `EntityPageCloseRequested` (`onto-file-viewer-tile`). Fullscreen occurrences are reported from `fullscreenchange`, not from the button handler, so leaving fullscreen with Escape or the browser's own UI produces `TileRestored` exactly as clicking the control does — and fullscreen is `SurfaceObscured`/`SurfaceRevealed` (the Tile covers the presentation), never a resize.
- The `show-details-requested` and `entity-selected` Presentation Global Events are gone as a parallel semantic bus. Opening a file's page now runs `EntityPageOpenRequested` (Component) -> dDock -> `EntityPageRequested` (Shared) -> `onto-file-viewer-tile`/the preview Tiles reveal themselves; closing it runs the mirror chain `EntityPageCloseRequested` -> `EntityPageDismissRequested`, including the standalone viewer page's `postMessage`, which used to hide the Tile directly. The requesting Tile no longer performs the consumer's responsibility. `EntitySelected` is still announced but is not a `view:ComponentEvent` in the Release 8 policy, so the Listener promotes it to nothing — the intended outcome for an occurrence whose meaning stays local. `onto-photo-tile`'s ad-hoc `photo-selected`/`photo-open-requested` names were the same two occurrences under a Tile-private vocabulary and now use the presentation one.

### Added

- `ontobdc_view.dock`: the dDock Python runtime and the authority over promotion. It reads `view:promotesTo` as the multivalued relation it is (`Graph.objects`, never a single-object read that would silently drop the second target of `TileOpened`), indexes the policy once per page rather than parsing or querying per interaction, and answers with zero, one or many Shared Events — an absent `promotesTo` simply means no promotion, not an error. The `PresentationEventPromotionListener` plugin is discovered by walking `dock/plugin/listener/`, the same convention every other OntoBDC plugin resource uses, and runs the promotion statechart `EventReceived -> SemanticEventResolved -> PromotionPolicyEvaluated -> PromotionTargetsResolved -> ResponseProduced`. Every module imports only the standard library and rdflib, because it executes inside Pyodide.
- `component_event_promoter.js`: the single Component -> Shared path in the browser, filling the Release 8 scaffold of that name rather than adding a second promoter. It receives the Component Event, hands the envelope to the Python Listener through Pyodide, announces each promotion on the Surface's event bar and dispatches each Shared Event (`ontobdc:shared-event`) — and holds no map, switch, table or registry of its own. Occurrences that arrive before the runtime is up are queued and replayed in order; a runtime that fails to boot is reported explicitly on the bar and in the console, and the queue is kept. There is deliberately no JavaScript fallback. Transport is JS -> Pyodide -> Python in-process: no server, socket, WebSocket, SSE or HTTP, and the policy document travels embedded in the page, so `file://` operation is unaffected. A page runtime that already owns a Pyodide instance (WorkStream, Gantt) has it reused, under that runtime's own lock.
- `ontobdc_view.component_event_promoter_source()`, `listener_runtime_source()` and `presentation_event_policy()` — the built bridge and the two pieces it is assembled from, so a host can package them itself. The policy document is read through the central `OntologyConfigAdapter` (new `obdc_abox_presentation_events` prefix), never from a copy bundled in this package.

### Fixed

- Connecting a folder to the IfcWorkSchedule Gantt (and to the WorkStream Page, which renders the same shared container runtime) failed with “The selected folder holds more than one dataset. Pick the schedule's own folder.” whenever the picked container held more than one dataset — the normal shape of a real container, where each schedule, checklist and budget is its own dataset folder. There was nothing the reader could do about it: the Page is served from the container root, so the root is the folder to pick, and picking a single dataset folder instead is what the message asked for without naming which one. The walk now reads the dataset folder name the Page already carries in its payload (`datasetFolder`) and returns that folder, so a container with any number of datasets connects on the first try. It also no longer stops after the third dataset found, which by itself put the Page's own folder out of reach as soon as it was the fourth one walked. When the Page's dataset genuinely is not under the selection, the error now names the datasets that were found instead of only saying there were several — in English, Brazilian Portuguese, European Portuguese and Spanish.
- The IfcWorkSchedule Gantt now exposes the missing printer action. It opens the browser's native print/PDF flow and applies an A4-landscape print layout that keeps the task table and timeline while removing navigation, dialogs and editing controls. The action's title and accessible name are available in English, Brazilian Portuguese, European Portuguese and Spanish. Before a project folder is loaded and validated, every Gantt action other than the project loader is disabled; connecting enables them as one coherent state, while a failed connection keeps them blocked.
- `onto-image-file-tile`/`onto-csv-file-tile` no longer read the real file they preview while closed. `data-tile-closed`/`ComponentMetadata.default_closed` only ever hid these Tiles visually; `connectedCallback` still unconditionally set `img.src`/called `fetch()` against the entity's real `obdc:filePath`, so every per-file preview Tile in a Surface read its real file the moment the page loaded, invisible but not free — on a container living inside a cloud-synced folder (OneDrive Files On-Demand and equivalents), opening the generated `index.html` forced every image/CSV in the container to download. Both Tiles now defer that read until `data-tile-closed` is actually cleared (i.e. the file is opened from `onto-file-tree-tile`).
- `onto-presentation-surface` (any Surface) rendered as a fully blank page: the H5 debug-instrumentation object `DBG_SURFACE` was `Object.freeze()`-d, but `connectedCallback`/`#layoutSynchronous` unconditionally increment its counters (`DBG_SURFACE.connectedCount += 1`, etc.) on every call — a write to a frozen property throws in the strict-mode-by-default `<script type="module">` these Tiles are embedded as, crashing before anything renders. Removed the freeze; the object was always meant to stay a live, mutable counter bag.
- The H5 perf pass (O(N²)→O(N) layout, RAF-debounced `#scheduleLayout()`) silently made the entire imperative public API (`present`/`dismiss`/`bringToFront`/`sendToEnd`/`relayout`/`close`/`pin`/`unpin`) asynchronous: each still dispatches its `surface-tile-*` event synchronously right after scheduling, so any caller reading `dataset.surfaceState` (or CSS driven by it, e.g. a just-`close()`d Tile's `display:none`) immediately afterward observed the *pre-call* layout until the next animation frame — the `data-tile-closed`/`data-surface-state="unplaced"` mechanism that keeps closed per-file preview Tiles out of the grid depends on exactly this. Added `#flushLayout()` (cancels any pending coalesced frame, runs layout immediately) and switched all 8 of those one-shot public methods to it; the genuinely high-frequency internal triggers the H5 pass targets (`ResizeObserver`, the childList/`surface-region` `MutationObserver`, `attributeChangedCallback`, `slotchange`) are untouched and still coalesce via `requestAnimationFrame`.
- `onto-pdf-file-tile`'s `<embed>` had the same unconditional-real-read gap as the image/CSV Tiles above, just missed the first pass (the search covered `fetch()`/`img.src`, not `<embed src>`): `#render()` set it whenever the Tile was connected, closed or not. Gated behind `data-tile-closed` the same way.

### Changed

- The main Surface (`index.html`) no longer embeds a per-file preview Tile (`onto-image-file-tile`/`onto-pdf-file-tile`/`onto-csv-file-tile`/`onto-generic-file-tile`) for every file entity in the container — a real container can have thousands, and even with every one of them correctly deferring its own real-file read (the three fixes above), that's still thousands of closed-but-connected custom elements sitting in the DOM, each one entity type away from silently regressing back into this exact bug class. `ImageFile`/`PdfFile`/`CsvFile`/`GenericFile` are no longer declared `obdc:SurfaceableEntity` (`ontobdc`'s `data_gathered.py`), so `SurfaceMatchedCapability`'s auto-match no longer creates a Tile for them at all; the main Surface now only ever shows RO-Crate metadata (name, size, the file tree). Opening a file (`onto-file-tree-tile`, double-click) reveals a single, Surface-wide `onto-file-viewer-tile` — one instance, always present but closed by default, `tile_class`-matched like `onto-file-size-tile` rather than auto-matched per entity — whose `<iframe>` points at the standalone `onto-file-viewer.html` page (written alongside `index.html` at the container root by `ontobdc`'s `SurfacePackagedCapability`) with the file's path passed by reference in the query string (`?path=...`). That page is the one place, and an explicit double-click the only moment, any real container file is ever read; the `<iframe>`'s `src` itself stays unset until `data-tile-closed` actually clears, so the Tile being present-but-closed in the DOM never triggers a read on its own. `onto-image-file-tile`/`onto-pdf-file-tile`/`onto-csv-file-tile`/`onto-generic-file-tile` remain in the package (their own gating fixes above still stand on their own merits) but are no longer part of the live matching path. (`onto-file-tree-tile`'s double-click briefly opened the viewer page in a new tab via `window.open()` instead — reverted in favor of the inline iframe Tile, which keeps the interaction inside the Surface itself.)

### Changed

- Moved the Tile `ComponentPort` descriptors here from the `ontobdc` package (`view.plugin.component` → `ontobdc_view.component.plugin`), and moved this package's own JS/CSS assets from `assets/components/` to `component/asset/`, aligning both under a shared `component/` root with singular naming throughout (`component`, `plugin`, `asset` — no plural segments). `__init__.py`'s `asset_root()`/`component_path()` and `build.py`'s template loader were updated to match. `ontobdc` was added as a declared dependency of this package, since the moved descriptors import `ontobdc.shared`/`ontobdc.storage`.
- Replaced the single "Annotate" button on each dimension card with an inline-annotations view/create icon pair: view opens a tile listing that resource's annotations directly below the active dimension card; create opens the existing annotation editor. Buttons now sit immediately next to their label instead of being spread across the card via `space-between`.
- Each dimension card is now full width (was a fixed narrower width), matching the surrounding Tile's own width convention.
- Toned down the geometry drag handle from a solid accent-cyan disc (which read as a second, competing marker) to a muted, translucent grey ring layered over the actual marker.
- Replaced the "Saved" feedback on the annotation editor's Save button (previously a button-text change, easy to miss) with a visible animated toast.
- `_read_component_sources()` (in `ontobdc`'s `surface_packaged.py`) now calls this package's `component_source(tag)` through the new `ComponentSourcePort` (see `ontobdc`'s changelog) instead of `ontobdc` doing its own hardcoded builder-name lookup into this package.
- Removed the `ontobdc` runtime dependency declaration from `pyproject.toml`. `ontobdc` already imports this package dynamically at runtime without a formal pip dependency in that direction (`ComponentLoader._load_ontobdc_view_components`, `SurfacePackagedCapability`); this package no longer declares one back, either — the two are still expected to be co-installed, just not coupled via a formal dependency edge in either `pyproject.toml`.

### Known gaps

- This package is not yet published to PyPI. `ontobdc` imports it at runtime for Tile discovery (`ontobdc.shared.adapter.loader.ComponentLoader`) but does not declare it as a dependency — see the `ontobdc` package's changelog. Publishing this package and declaring the dependency for real is a prerequisite before Tiles can be relied on in a packaged `ontobdc` release.
